# testRail

## Purpose

Contains Python scripts for synchronizing automated test results back to TestRail, Tubi's test case management platform. These scripts parse test execution results and update corresponding TestRail test cases with pass/fail status.

## Structure

- `__init__.py` - Python package initializer
- `testrail.py` - TestRail API client class providing authenticated HTTP methods (GET, POST) for the TestRail REST API
- `result_parser.py` - Parses automated test result files (e.g., Mocha/Mochawesome output) and maps them to TestRail case IDs
- `result_updater.py` - Updates TestRail test runs with parsed results
- `sync_to_testrail.py` - Main entry point script that orchestrates parsing results and syncing them to TestRail

## Architecture

- **Parse → Map → Update Pipeline**: Test results from automated runs are parsed, mapped to TestRail case IDs (extracted from test names or comments), and then bulk-updated in TestRail via the API.
- **Python-Based**: This module uses Python (separate from the Node.js-based test suite) for TestRail integration, likely for historical reasons or Python library availability.

## Dependencies

**Internal:**

- Consumes test result files generated by `js/automated-tests/` test runs
- Uses TestRail case IDs embedded in test file names/comments

**External:**

- TestRail API (`tubi.testrail.io`)
- Python 3 runtime
- `requirements.txt` (in project root) for Python dependencies

## Working with this Code

### Prerequisites

- Python 3 installed
- TestRail API credentials (environment variables)
- `pip install -r requirements.txt` from project root

### Build & Run

- `python testRail/sync_to_testrail.py` - Sync latest test results to TestRail

### Things to Watch Out For

- TestRail API credentials must be available as environment variables.
- Test case IDs in automated tests must match TestRail case IDs for results to sync correctly.
